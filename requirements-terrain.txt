# Dependencies for .github/workflows/fetch_terrain.yml (pipeline/fetch_terrain.py)
# and .github/workflows/terrain_radius_sweep.yml (pipeline/fetch_terrain.py AND
# scripts/mtn_obsc_area_sweep.py -- the sweep workflow installs this same file
# for both).
#
# Deliberately much lighter than requirements-pipeline.txt: neither script
# touches NBM data, so none of the GRIB2 stack (herbie/xarray/cfgrib/pandas)
# is needed. That matters most for fetch_terrain.yml, which downloads 1,708
# tiles before it does anything else -- paying an unnecessary install cost
# on every run.
#
# This file exists because the list used to be inline in the workflow
# (`pip install requests numpy scipy affine`) with nothing checking it.
# When the land-only baseline change made compute_output_grids import
# pipeline.boundaries -> pipeline.polygons, the job began needing shapely
# and scikit-image, nobody updated the inline list, and the run died with
# ModuleNotFoundError AFTER downloading all 1,708 tiles.
# tests/test_workflow_dependencies.py now pins this file against what each
# entry point actually imports.

requests        # tile downloads (imported lazily inside the fetch functions)
numpy
scipy           # maximum_filter1d / uniform_filter for the ridge search
affine          # pipeline.grid_spec.GridSpec.to_affine()

# Both reached through pipeline.boundaries, for the land mask the
# land-only baseline needs: shapely unions the coastline features,
# scikit-image rasterizes the union onto the mosaic grid. NOT needed
# before that change, which is how the drift happened.
shapely
scikit-image

# pyproj and geojson are NOT needed by pipeline/fetch_terrain.py itself --
# pipeline/polygons.py imports both lazily, inside the functions that wrap
# or measure finished polygons, strictly hazard-output work downstream of
# anything terrain does (see that file's note, and
# test_the_terrain_job_does_not_quietly_acquire_the_hazard_output_stack
# above, which still guards fetch_terrain.py specifically). But
# scripts/mtn_obsc_area_sweep.py -- the other entry point this file now
# serves -- calls pipeline.hazards.mtn_obsc.polygonize_mtn_obsc_grid
# unconditionally, which reaches both of those lazy imports on every run
# that produces at least one polygon (filter_polygons_by_area's geodesic
# area calc needs pyproj; polygons_to_feature_collection needs geojson).
# Both hops are function-level imports inside a NON-entry-point file
# (pipeline/polygons.py), which is exactly the shape of import
# tests/test_workflow_dependencies.py's static walker cannot see --
# confirmed missing only by actually running the sweep script, not by
# that test. Keep both declared here for that script's sake even though
# fetch_terrain.py never touches them.
pyproj
geojson
